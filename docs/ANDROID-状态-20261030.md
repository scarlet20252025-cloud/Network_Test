## ❗ 当前仍存在的问题（下一步从这里开始）

### 现象

点「开始借网」后：

```
自检结果：3/5 项通过 —— 隧道没完全通
① TUN 网卡      ✅ 198.18.0.1/30 存在
② 隧道进程      ✅ hev 在跑
③ DNS 解析      ✅ www.qq.com → 198.18.64.31（fake-ip，正常）
④ HTTP          ❌ curl 返回 000
⑤ 隧道承载      ❌

手机 ip route 只剩一条：
    198.18.0.0/30 dev tun0 proto kernel scope link src 198.18.0.1
    ↑ 没有任何公网路由！

手机 nc 10.13.24.1 1080  →  "Network is unreachable"
```

### 但策略路由表是有的

`ip route show table all` 里有 65 条，其中 table 1055 里有完整的
`PUBLIC_V4` 那 47 条（1.0.0.0/8、2.0.0.0/7 ... 208.0.0.0/4 都指向 dev tun0）。

**所以路由建了，但没生效。** 主路由表里没有，说明 Android 只把它们
挂在了 VPN 的独立路由表（1055），需要 `ip rule` 把流量导过去。

### 怀疑方向（按可能性排序）

1. **`ip rule` 没有指向 table 1055 的规则**
   之前（VPN 首次建立时）看到 table 1054 有规则，现在变成 1055，
   可能是 netId 变了但规则没跟上。

2. **`addDisallowedApplication(getPackageName())` 的副作用**
   把 App 自己排除在 VPN 外之后，`adb shell`（uid 2000）和 App（uid 10293）
   可能都不在 VPN 覆盖范围内 —— 但 `curl` 是从 shell 发的，
   而 **真正的浏览器流量应该走 VPN**。所以这条可能只是「shell 测不准」。

3. **Android 10+ 的 `setMetered(false)` + `addRoute` 组合问题**

### 下一步（明确的验证顺序）

```bash
# 1. 看 ip rule 有没有指向 1055
adb shell ip rule

# 2. 从「App 自己」而不是 shell 发请求（shell 可能被 disallowed 排除）
#    用 App 内的自检按钮，看它报的具体是哪两项失败

# 3. 如果确认是 ip rule 缺失，检查 FerryVpnService 的 Builder 配置
#    特别是有没有调用 setBlocking / allowFamily / 遗漏的 addRoute
```

## 阻塞项

**vivo 拒绝 adb 安装**：`INSTALL_FAILED_ABORTED: User rejected permissions`
即使屏幕唤醒 + `verifier_verify_adb_installs=0` 也一样。
需要用户在手机上：设置 → 系统管理 → 开发者选项 → **USB 安装**（打开）
