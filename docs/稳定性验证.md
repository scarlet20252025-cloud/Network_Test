## 一、修复的三个关键 bug

### 1.1 系统代理写了 SOCKS5 端口（浏览器完全打不开）

**现象**：用户报「开启借网之后，浏览器都不能访问了」。

**根因**：`borrow-net.ps1` 的回退逻辑：

```powershell
$sysProxy = "127.0.0.1:$SocksPort"                    # 10808 = SOCKS5
if ($bridgeOk) { $sysProxy = "http://127.0.0.1:$HttpPort" }
```

当 dual-proxy 没起来时，把系统代理写成纯 SOCKS5 端口。
**Windows 系统代理（WinINET）只支持 HTTP 代理**，所有读系统代理的程序
（浏览器 / .NET / Electron）会把 SOCKS5 端口当 HTTP 代理连 → 全部秒失败。

实测：
```
ProxyServer = 127.0.0.1:10808
GetSystemWebProxy().GetProxy(baidu) = http://127.0.0.1:10808/
Invoke-WebRequest baidu → An error occurred while sending the request.
```

**修复**：HTTP 代理没起来时**直接 return，绝不写系统代理**。
另外在 `On` 分支开头主动检测「系统代理是否被写成 SOCKS 端口」，发现即修复。

### 1.2 通配池借用了错误的 IP（gist 全部超时）

**现象**：`https://gist.githubusercontent.com` 经代理必超时 25s。

**根因**：通配匹配逻辑

```javascript
// 旧代码
for (const suf of WILDCARD_SUFFIX) {
  if (h.endsWith('.' + suf)) return POOL[suf] || POOL['github.com'];
}
```

`gist.githubusercontent.com` 匹配到后缀 `githubusercontent.com`，
该键不存在 → **退回 `POOL['github.com']`** → 拿 `140.82.x` 的 IP 去连
`gist.githubusercontent.com`（真实 IP 是 `185.199.x`）。IP 和 SNI 都不对，必超时。

**修复**：显式映射，绝不跨域名借 IP。

```javascript
const SUFFIX_POOL = {
  'github.com': 'github.com',
  'githubusercontent.com': 'raw.githubusercontent.com',  // 实测同一批 185.199.x
  'githubassets.com': null,
  'github.io': null,
};
```

### 1.3 健康分缓存无衰减 + 无总预算（间歇性全失败）

**现象**：连续 15 次 github，**前 9 次全失败（每次 20s 超时）、后 6 次全成功**。

**两个原因**：

**① HEALTH 缓存累加不衰减**

```javascript
// 旧代码：只加不减
h.fail += 1;
```

dual-proxy 是常驻进程，跑几百次测试后所有 IP 的 fail 都累计到几百，
score 全变负、排序完全失去意义。

修复：只统计最近 **60 秒**内的事件，旧数据自动过期。

**② 没有总超时预算**

```javascript
// 旧代码：8 个 IP × 6s + dual-proxy fallback 20s = 最坏 38s
const perTryTimeout = opts.perTryTimeout || 6000;
```

浏览器等不到 38s 就判超时了，用户看到的就是「打不开」。

修复：加 `totalTimeoutMs`（默认 8s），到点无论剩多少都判失败。
同时收紧 `perTryTimeout` 到 3.5s、`concurrency` 提到 4、`staggerMs` 降到 400ms。

## 四、带宽复测（推翻第一版结论）

第一版报告说「远端带宽上限 1 MB/s」，**错了**。

错因：只用清华源单一源测速。清华源在 CERNET，办公网到 CERNET 路由极差。

多源实测：

| 源 | 单线程 | 4 线程 |
|---|---|---|
| **华为云** | **89–92 MB/s** | 74.93 MB/s |
| 清华 CERNET | 1.12 MB/s | 1.05 MB/s |

**同一台机器、同一时刻，差 80 倍。**


**借网比直连快 4.7 倍。**

## 五、并发竞速机制说明

`smart-resolve.mjs` 的 `connectBest()` 用 Happy Eyeballs 思路：

```
按健康分排序 → 立即发第 1 个
             → 每 400ms 补发一个（最多 4 个在飞）
             → 任一个成功立刻返回，其余销毁
             → 8s 总预算到点全判失败
```

健康分公式：

```javascript
score = staticOk + recentOk*12 - recentFail*18
if (最近15s内失败过) score -= 30
```

`recentOk` / `recentFail` 只统计**最近 60 秒**的事件。

**为什么不用串行**：池里有黑洞 IP（`20.205.243.166` 是 DNS 默认返回但实测 0/3），
串行会先等满一个超时才试下一个。

## 六、已知限制

1. **`gist.github.com` 不可达** —— 远端办公网封锁 `159.24.3.173`，与本工程无关。
   gist 的 raw 内容（`gist.githubusercontent.com`）可正常访问。
2. **带宽受源侧影响** —— 同一台远端，不同下载源差 80 倍。
   大文件优先用华为云 / 阿里云，避免清华 CERNET 源。
3. **远端到 github 有轻微波动** —— `correlate.mjs` 同时刻对比显示
   远端直连 16/18、隧道 17/18，两者基本同步波动，说明是办公网出口的问题，
   靠并发竞速 + 健康分缓存吸收掉了。
4. **系统代理依赖 dual-proxy 存活** —— 若 dual-proxy 挂掉，`borrow-net.ps1 On`
   会拒绝切系统代理（这是保护，不是故障）。此时应用可自行配 SOCKS5 10808。
