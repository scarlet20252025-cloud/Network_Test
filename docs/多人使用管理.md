# 多人使用管理

> **前提认知（2026-10-23 实测）**：校园网对学生账号之间有隔离，而且是**端口级**的。
> 从另一个账号的机器探测本机：`22` 不通、`445` 通、`10803` 通。
> 所以「把某台机器上的代理开放出去给大家用」这个方案**不可靠** ——
> 哪些端口能过完全看网管策略，随时会变。

**因此本方案的设计是：每台机器各自建隧道直连远端。**
远端是唯一的共享点（一台机器、一个出口、N 条 SSH 隧道，互不影响）。

---

## 一、架构

```
                  ┌─ 使用者 A 的机器 ──ssh -D──┐
                  │                            ├─→ 远端 pcs ─→ Internet
  校园网（账号隔离）├─ 使用者 B 的机器 ──ssh -D──┤
                  │                            │
                  └─ 本机（管理端）──ssh -D────┘
```

**每个人一条独立隧道**，好处：

- 谁断网不影响别人
- 流量可按人统计（见下面「多用户」）
- 不需要在我的机器上开任何入站端口

---

## 二、使用者接入（两分钟）

在**使用者自己的机器**上跑：

```powershell
powershell -ExecutionPolicy Bypass -File setup-client.ps1 -RemoteHost pcs
```

脚本会自动做四件事：

1. 检测 / 生成 SSH 密钥
2. 测试能否免密直连远端；**不行就把公钥和添加命令打印出来**，
   你去远端加一下再重跑即可
3. 启动隧道保活 + 双协议代理（端口自动探测）
4. 验证并打印「应用里该填什么」

脚本输出的最后一段就是配置说明，直接照抄。

### 如果脚本提示「还不能免密登录」

在**能管理远端的那台机器**上执行一次（把脚本打印的公钥贴进去）：

```powershell
# Windows 远端，管理员 PowerShell
Add-Content C:\ProgramData\ssh\administrators_authorized_keys '<脚本打印的那一串>'
```

或者远端是 Linux：

```bash
echo '<那一串>' >> ~/.ssh/authorized_keys
```

> ⚠️ Windows 远端的 `administrators_authorized_keys` 要求 ACL 只有
> SYSTEM + Administrators。用 `Add-Content` 追加不会破坏原有 ACL，
> 但如果是新建文件，需要：
> `icacls <文件> /inheritance:r /grant:r "SYSTEM:(F)" /grant:r "Administrators:(F)"`

## 三、管理员怎么管（这条链路是给我自己用的）

### 3.1 加人 / 删人 / 停用

```powershell
node tools\proxy-admin.mjs add 张三 --note "3 楼实验室"   # 加人，打印令牌
node tools\proxy-admin.mjs list                          # 看全部
node tools\proxy-admin.mjs disable 李四                   # 停用（令牌立即失效）
node tools\proxy-admin.mjs enable 李四                    # 恢复
node tools\proxy-admin.mjs reset 王五                     # 重置令牌（怀疑泄露时用）
node tools\proxy-admin.mjs remove 王五                    # 删除
```

### 3.2 给使用者发配置

```powershell
node tools\client-config.mjs 张三               # 生成 cmd（双击即用）
node tools\client-config.mjs 张三 --format md   # 生成说明文档（贴微信）
node tools\client-config.mjs 张三 --format sh   # Linux/macOS
```

生成的文件在 `client-configs\` 下，**包含地址、用户名、令牌**，
发给人之后对方不用自己填任何东西。

### 3.3 改全局设置

```powershell
node tools\proxy-admin.mjs settings                          # 看当前
node tools\proxy-admin.mjs settings --max-conns 20           # 每人最多 20 连接
node tools\proxy-admin.mjs settings --daily-mb 500           # 每人每天 500MB
node tools\proxy-admin.mjs settings --auth off               # 临时关认证（仅调试）
```

**改完立即生效，不用重启代理**（热加载，120ms 内）。

## 四、状态显示

面板地址由 `.proxy-state\ports.json` 里的 `panel` 字段给出，浏览器打开即看：

```
http://127.0.0.1:<panel>/
```

内容：

| 区块 | 显示什么 |
|---|---|
| 概览卡片 | 累计连接 / 当前活跃 / 成功 / 失败 / 协议分布 |
| **用户表** | 每人一行：在线指示灯、令牌前缀、当前连接数、上下行流量、累计连接、最后活跃 |
| 最近连接 | 时间、协议、目标、**是哪个用户**、耗时 |
| 拒绝记录 | 谁在试、什么原因（`bad-token` / `unknown-user` / `too-many-connections`） |

每 1.5 秒自动刷新。「最后活跃」用相对时间（`3 分钟前`），一眼看出谁在用。

## 五、认证怎么用

### 使用者侧

同一个端口，HTTP 和 SOCKS5 都支持，**用户名/令牌是同一套**：

```bash
# HTTP
curl -x http://127.0.0.1:10809 -U '张三:abc123-xyz' https://github.com

# SOCKS5（端口相同，自动识别）
curl --socks5-hostname 127.0.0.1:10809 -U '张三:abc123-xyz' https://github.com
```

浏览器用 SwitchyOmega / FoxyProxy：
协议 SOCKS5，端口填同一个，认证填用户名 + 令牌。

### 错误码含义

| 现象 | 原因 |
|---|---|
| HTTP `407` | 没带凭据，或令牌错，或用户被停用 |
| HTTP `429` | 超过 `maxConnsPerUser` |
| SOCKS5 握手后立即断 | 同上，只是 SOCKS5 没有 407 这个概念 |
| 面板「拒绝记录」出现 `unknown-user` | 有人在爆破用户名 |

## 六、配额怎么保护出口

实测远端出口充裕（华为云 90+ MB/s），但被多人同时拉大文件还是会占满。
两道闸：

1. **连接数上限**（`maxConnsPerUser`，默认 40）—— 防单用户开太多连接
2. **每日流量**（`dailyBytesPerUser`，默认不限）—— 需要时再开

第二道闸目前只统计、不强制（`Authenticator` 里已有 `bytesIn/bytesOut`
累计，做强制只需在 `checkAuthHttp` 加一次比较）。要开的话告诉我。

## 七、已知限制

1. **没有按域名/端口的 ACL** —— 任何人连上就能访问所有站点。
   要做白名单（比如只允许 GitHub）需要在 `smartConnect` 前加一层目标过滤。
2. **流量统计重启后清零** —— `Authenticator.sessions` 是内存态。
   `users.json` 里的 `stats` 只累计连接数和最后活跃时间，没存字节数
   （避免每次请求都写盘）。
3. **令牌是明文存储** —— `users.json` 里能看到。这台机器本身要管好，
   不要把这个文件同步到公开仓库。
4. **远端 sshd 要允许并发** —— 默认就允许，但如果改了 `MaxStartups`
   或用了 fail2ban，人多时要相应调大。
