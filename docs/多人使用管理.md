# 多人使用管理

> **前提认知（实测）**：校园网对学生账号之间有隔离，而且是**端口级**的。
> 从另一个账号的机器探测本机：`22` 不通、`445` 通、`10803` 通。
> 所以「把某台机器上的代理开放出去给大家用」这个方案**不可靠** ——
> 哪些端口能过完全看网管策略，随时会变。
>
> **因此本方案的设计是：每台机器各自建隧道直连远端。**
> 远端是唯一的共享点（一台机器、一个出口、N 条 SSH 隧道，互不影响）。

---

## 一、架构

```
                  ┌─ 使用者 A 的机器 ──ssh -D──┐
                  │                            ├─→ 远端 ─→ Internet
  校园网（账号隔离）├─ 使用者 B 的机器 ──ssh -D──┤
                  │                            │
                  └─ 本机（管理端）──ssh -D────┘
```

**每个人一条独立隧道**，好处：

- 谁断网不影响别人
- 流量可按人统计与限速
- 不需要在我的机器上开任何入站端口

---

## 二、使用者接入（三种方式）

### 方式 A：登录门户（推荐）

浏览器打开 **`http://ferry.internal:8080/`**（或 `http://10.13.24.1:8080/`）：

1. 输入**自己的局域网 IP**（`ipconfig` 里的 IPv4 地址）
2. 输入**管理员给的临时密钥**（8 位，默认 12 小时有效，**只能用一次**）
3. 登录后下载 `ferry-<你的IP>.cmd`，双击运行

部署包自动完成：检测/生成 SSH 密钥 → 建隧道 → 起双协议代理 →
设系统代理 → 注册开机自启。**全程无需手工配置。**

> 第一次需要把公钥发给管理员加到远端（部署包会打印出来），之后不用管。

### 方式 B：命令行

```powershell
powershell -ExecutionPolicy Bypass -File tools\setup-client.ps1 -RemoteHost pcs
```

### 方式 C：只建隧道，自己配应用

```powershell
powershell -ExecutionPolicy Bypass -File tools\ferry.ps1 -Action On -ProxyMode App
```

## 三、局域网域名

**`ferry.internal`**

- `.internal` 是 ICANN 在 2024 年正式保留给私有网络使用的 TLD。
  永远不会被公网 DNS 解析占用，也不可能被抢注。
- 比 `.local`（被 mDNS 占用）、`.lan`（非标准）都干净。

配置（可选，不改也能用 IP 访问）：

```powershell
# 管理员 PowerShell
$f = "$env:SystemRoot\System32\drivers\etc\hosts"
$line = "10.13.24.1  ferry.internal"
if (-not (Select-String -Path $f -Pattern 'ferry.internal' -Quiet)) {
  Add-Content -Path $f -Value $line -Encoding ASCII
}
```

门户的 `/setup-hosts` 页面也给了这段命令。

## 四、管理员怎么管

### 4.1 用户与令牌

```powershell
node tools\proxy-admin.mjs add 张三 --note "3 楼实验室"   # 加人，打印令牌
node tools\proxy-admin.mjs list                          # 看全部
node tools\proxy-admin.mjs show 张三                      # 打印该用户完整接入说明
node tools\proxy-admin.mjs disable 李四                   # 停用（令牌立即失效）
node tools\proxy-admin.mjs enable 李四                    # 恢复
node tools\proxy-admin.mjs reset 王五                     # 重置令牌（怀疑泄露时用）
node tools\proxy-admin.mjs remove 王五                    # 删除
```

### 4.2 全局设置

```powershell
node tools\proxy-admin.mjs settings                        # 看当前
node tools\proxy-admin.mjs settings --max-conns 40         # 每人最多 40 连接
node tools\proxy-admin.mjs settings --rate-mb 5            # 每人 5 MB/s（默认）
node tools\proxy-admin.mjs settings --daily-mb 500         # 每人每天 500MB（默认不限）
node tools\proxy-admin.mjs settings --auth off             # 临时关认证（仅调试）
```

**改完立即生效，不用重启代理**（热加载 120ms 内）。

### 4.3 临时密钥（门户）

访问 `/admin`，用 `portal-admin.txt` 里的密码登录。

| 操作 | 说明 |
|---|---|
| 创建密钥 | 填备注 + 有效小时数；**明文只在生成时显示一次**，之后只剩前缀 |
| 撤销密钥 | 立即失效，即使还没用过 |
| 停用账号 | 门户和部署包都拒绝该 IP |
| 重置令牌 | 旧的立即失效，需要重新下发部署包 |
| **解除锁定** | 见下 |

### 4.4 解除登录锁定

速率限制按来源 IP 记：**5 分钟内失败 5 次，锁 15 分钟**。

如果内网有人故意用错误密钥猛敲，会把该 IP 锁住 —— 连带坐在同一台
机器后面的无辜用户。这时去 **`/admin/unlock`**：

- 列出所有被锁的 IP，分「用户登录」和「管理登录」两类，各自剩余时间
- 点「解除」立即放行

> 反复被锁说明有人在试 —— 应该**先换密钥**，而不是反复解锁。

## 五、每账号限速

默认 **5 MB/s**，按用户（不是按连接）计。一个人开 40 条连接也只共享这 5 MB/s。

### 实测精度

| 设定 | 源速率 | 实测 | 误差 |
|---|---|---|---|
| 5 MB/s | 充足（本地回环） | 5.00 MB/s（20MB / 4.00s） | 0% |
| 0.5 MB/s | 0.91 MB/s | 0.49 MB/s（5.87MB / 12.0s） | 2% |
| 不限 | 0.91 MB/s | 0.91 MB/s | — |

### 实现用 GCRA，不是令牌桶

令牌桶的问题：初始给满一桶（= 1 秒配额），前 1 秒流量完全免费。
实测 5MB @ 2MB/s 只花 1.03s（超速 **2.4 倍**）、20MB @ 5MB/s 实测 8.08 MB/s。

GCRA 只维护「下一个包最早可发时间」，没有初始免费额度，速率天然准确。

### 转发层

所有转发走队列式 `pipeLimited`：

- `'data'` 只负责入队，单泵按节奏出队
- 队列有 1MB 高水位，超了 `pause()` 上游（真背压）
- 只有队列空且上游结束才 `dst.end()`

> ⚠️ 不能用「`pause()` 后 `setTimeout`」那版：Node 在 pause 生效前
> 可能已 emit 多个缓冲 chunk，多个 `setTimeout` 并发排队、顺序错乱，
> 实测 5MB 丢 64KB。

## 六、状态显示

浏览器打开面板（端口见 `.proxy-state/ports.json` 的 `panel` 字段）：

```
http://127.0.0.1:<panel>/
```

| 区块 | 显示什么 |
|---|---|
| 概览卡片 | 累计连接 / 当前活跃 / 成功 / 失败 / 协议分布 |
| **用户表** | 每人一行：在线指示灯、令牌前缀、当前连接数、上下行流量、累计连接、最后活跃 |
| 最近连接 | 时间、协议、目标、**是哪个用户**、耗时 |
| 拒绝记录 | 谁在试、什么原因（`bad-token` / `unknown-user` / `too-many-connections`） |

每 1.5 秒自动刷新。「最后活跃」用相对时间（`3 分钟前`）。

## 七、认证怎么用

同一个端口，HTTP 和 SOCKS5 都支持，**用户名/令牌是同一套**：

```bash
# HTTP
curl -x http://127.0.0.1:10802 -U '张三:abc123-xyz' https://github.com

# SOCKS5（端口相同，自动识别）
curl --socks5-hostname 127.0.0.1:10802 -U '张三:abc123-xyz' https://github.com
```

### 错误码含义

| 现象 | 原因 |
|---|---|
| HTTP `407` | 没带凭据，或令牌错，或用户被停用 |
| HTTP `429` | 超过 `maxConnsPerUser`（注意：门户那边 429 是速率锁定，含义不同） |
| SOCKS5 握手后立即断 | 同上，SOCKS5 没有 407 |

## 八、门户的安全措施

| 项 | 做法 |
|---|---|
| 密钥存储 | 只存 SHA-256，明文不落库 |
| 会话 | HMAC-SHA256 签名 cookie，库里只存 sid 哈希 |
| CSRF | 所有 POST 带一次性 token（包括解锁页的空列表状态） |
| 爆破防护 | 5 分钟 5 次锁 15 分钟，**用户/管理分开计数** |
| 响应头 | CSP / X-Frame-Options / nosniff / Referrer-Policy / Permissions-Policy |
| 开放重定向 | Location 只允许站内相对路径 |
| IP 校验 | 只接受私网段，公网 IP 直接拒 |
| 部署包越权 | 只能下载自己 IP 的包（比对 session 与 URL） |
| 时序攻击 | 令牌/密码比较用 `hmac.compare_digest` |

**为什么用户/管理分开计数**：共用计数的话，普通用户故意输错 5 次
就能把管理员的登录也锁了 —— 低权限影响高权限，方向反了。

## 九、已知限制

1. **没有按域名/端口的 ACL** —— 任何人连上就能访问所有站点。
   要做白名单需在 `smartConnect` 前加目标过滤。
2. **流量统计重启后清零** —— `Authenticator.sessions` 是内存态。
   `users.json` 里的 `stats` 只累计连接数和最后活跃时间。
3. **令牌明文存 `users.json`** —— 这台机器本身要管好，
   不要把该文件同步到公开仓库（已在 `.gitignore`）。
4. **远端 sshd 要允许并发** —— 默认允许，但若改了 `MaxStartups`
   或用了 fail2ban，人多时要相应调大。
5. **门户是 HTTP 不是 HTTPS** —— 局域网内可以接受；临时密钥在
   局域网里明文传输，如果担心被嗅探，需自行加反向代理。
