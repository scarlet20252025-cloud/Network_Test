# 统一入口（mihomo 常驻）

> 目标：把「两条隧道 + 一个直连」合成**一个固定端点** `127.0.0.1:10810`，
> 自动选活的线路、自动切换，用起来不用记端口、不用改系统代理。
>
> 目录：`mihomo/`　主控：`mihomo/mihomo-keeper.ps1`

---

## 一、为什么需要它

在此之前，线路是「三个裸端口」：

| 线路 | 端口 | 出口 | 问题 |
|---|---|---|---|
| 直连 | 无 | 116.23.159.136 电信 | 学校限网时不能用 |
| SSH→pcs | `127.0.0.1:10801` | 218.107.0.47 联通 | 端口会顺延，得自己记 |
| WG→xt | `10.66.67.1:1080` | 116.23.159.136 电信 | **出口和直连相同** |

用哪条要人判断、要改系统代理、一条挂了要手动换。统一入口把这些收进一个端口。

**关键实测结论**：WG 线路的出口 IP 与直连**完全一样**（都是电信
116.23.159.136），所以它在「换运营商」这件事上零价值。它的唯一理论优势是
内核级隧道能承载 UDP，但上游两个 SOCKS 服务都只实现 TCP CONNECT
（`wireguard/ferry-socks5-server.py:90` 的 `if cmd != 1`；OpenSSH `-D` 同样
不支持 UDP ASSOCIATE），所以现阶段这个优势也是零。

真正的换出口靠 **SSH→pcs 的联通线路**。

## 二、怎么用

```powershell
cd E:\肥鱼不乐园\borrow-net\mihomo

.\mihomo-keeper.ps1 Status      # 看状态：线路、当前选中、三态出口、看护
.\mihomo-keeper.ps1 On          # 借网（ferry → ferry-auto，自动选活线路）
.\mihomo-keeper.ps1 Off         # 恢复直连（ferry → DIRECT）
.\mihomo-keeper.ps1 Switch ferry-ssh   # 强制指定某条线

.\mihomo-keeper.ps1 Start       # 启动 mihomo（不含看护）
.\mihomo-keeper.ps1 Watch       # 启动看护循环（自启跑的就是这个）
.\mihomo-keeper.ps1 Stop        # 停（会连看护一起停，否则 20 秒后被拉回来）
.\mihomo-keeper.ps1 Restart
.\mihomo-keeper.ps1 Test        # 自检：三态出口是否真的不同
.\mihomo-keeper.ps1 Install     # 装登录自启
.\mihomo-keeper.ps1 Uninstall   # 移除自启
```

**端点固定为 `127.0.0.1:10810`，HTTP 和 SOCKS5 同端口**，mihomo 自动识别协议。
需要代理的程序填这一个地址就行：

```powershell
curl.exe -x http://127.0.0.1:10810 https://myip.ipip.net
```

> ⚠️ 不要写 `curl --noproxy '*' -x ...` —— `--noproxy '*'` 会**覆盖** `-x`，
> 对所有主机禁用代理，请求根本没走代理。这个坑实测踩过，导致「三态出口全是电信」
> 的假象，白查一轮。

## 三、设计要点（每条都有踩坑背景）

### 1. 默认 DIRECT，不自动借网

`ferry` 组默认选 `DIRECT`。这是**故意的**：开机时如果校园网是通的，不应该
莫名其妙先走隧道。切到 `ferry-auto` 才是借网 —— 一个开关管「开/关借网」和
「选哪条线」两件事。

`config.template.yaml` 里 `profile.store-selected: false` 保证 mihomo 不记住
上次选择（否则测试时切到 ferry-wg，重启后直接就是 ferry-wg，会误判成默认值写错）。

### 2. 端口不写死，每次启动现场探测

SSH 隧道的 SOCKS 端口会顺延（10800 被占就 10801）。`ports.json` 只在
dual-proxy 以 auto 模式跑过时才更新，**手动起的 ssh -D 不写它** ——
实测 `ports.json` 记 10800、实际在听 10801，写死就连死端口。

所以 `Get-SshSocksPort` 按候选 `10800/10801/10808/10809` 逐个探测真实监听端口，
再渲染进 `config.yaml`。

### 3. 看护循环（Watch）—— 自启跑的是它，不是 Start

每 20 秒体检一次，做两件事：

- **mihomo 挂了** → 重新拉起
- **上游端口变了**（10801 → 10808）→ 重渲染配置 + 重启 mihomo

第二条是必需的：`config.yaml` 里的 port 是死的，mihomo 自己不会在新端口出现后
自动切过去。不重渲染的话，表现是「10810 还在听，但所有请求 502」。

带单例锁 + PID 复用防护（只比 PID 不够：强杀会留 lock，Windows 会把那个 PID
复用给任意新进程，新 keeper 看到「PID 存在」就自杀 —— 这个坑在
`tools/ssh-tunnel-keeper.ps1` 里已经踩过一次）。

### 4. 选择状态持久化（`mihomo-state.txt`）

`store-selected: false` 有个副作用：看护一旦因为上游端口顺延而重启 mihomo，
正在借网的用户会被**静默打回直连**（实测 11:18:14 那次自动重启后就回到了 DIRECT）。

解法是不看 mihomo 的 cache，自己记一个 state 文件：`On/Off/Switch` 时写入，
`Start-Mi` 成功后读回来。这样两个看似矛盾的需求都成立：

- 开机默认不借网（state 是 `DIRECT` 或文件不存在）
- 崩溃恢复后保持借网（state 是 `ferry-auto`）

### 5. 不动系统代理

本脚本**只提供端点**，不写 `HKCU\...\Internet Settings`。要不要把系统代理
指过来，由 `tools/ferry.ps1` / `渡口助手` 决定 —— 它们已经有「备份/还原用户
原代理」的逻辑，这里再动一次会打架。实测确认：`On` 之后
`ProxyEnable=1 ProxyServer=127.0.0.1:7897`（用户自己的 Clash Verge）纹丝不动。

## 四、分流规则

`config.template.yaml` 的 rules 只有五条：

```yaml
- IP-CIDR,127.0.0.0/8,DIRECT,no-resolve
- IP-CIDR,10.0.0.0/8,DIRECT,no-resolve
- IP-CIDR,172.16.0.0/12,DIRECT,no-resolve
- IP-CIDR,192.168.0.0/16,DIRECT,no-resolve
- MATCH,ferry
```

内网与回环永远直连 —— 借网时如果把这些也代理出去，局域网里的打印机、共享、
远端 SSH 会立刻失联。

**故意没有 `GEOIP,CN,DIRECT`**：这是借网工具，用户开它就是因为本地网不通，
国内站点也要走隧道。加了国内直连反而会让「借网」变成「只能上外网」。

## 六、自启

装好后启动文件夹有 `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\FerryMihomo.cmd`：

```bat
@echo off
chcp 936 >nul
rem 渡口统一入口 - 登录时拉起 mihomo（不切系统代理，只提供 127.0.0.1:10810）
start "" /min powershell.exe -NoProfile -WindowStyle Hidden -ExecutionPolicy Bypass -File "E:\肥鱼不乐园\borrow-net\mihomo\mihomo-keeper.ps1" -Action Watch
```

**这个 `.cmd` 必须同时满足三条**，每条都踩过：

| 要求 | 不满足时 |
|---|---|
| GBK 编码（不是 UTF-8） | `chcp 936` 下中文注释变乱码 |
| **无 BOM** | cmd.exe 把 BOM 三个字节当命令的一部分，首行 `@echo off` 失效，报 `'∩╗┐@echo' 不是内部或外部命令` |
| **CRLF 换行**（不是 LF） | 实测 `rem ...` 变成 `'em' 不是内部或外部命令` —— cmd 的解析器把行尾 CR 当命令终止符，纯 LF 会吃掉每行第一个字符 |

`Install` 动作里已处理这三条（`[Text.Encoding]::GetEncoding(936)` +
`-replace` 转 CRLF）。

用启动文件夹而不是计划任务：`schtasks` 需要管理员，实测 `Access denied`。

## 七、已知限制

1. **只有 TCP**。两个上游都只支持 SOCKS5 CONNECT，UDP 走不通。
   游戏、QUIC、部分视频通话不能用。
2. **不是「普通网络」**。这只是个 SOCKS5/HTTP 端点，只覆盖「认代理设置」的程序。
   要全局透明代理必须 TUN，而 TUN 需要管理员
   （实测 `Start TUN listening error: configure tun interface: Access denied`）。
3. **`mihomo` 二进制借用 Clash Verge 的**（`D:\Clash Verge\verge-mihomo.exe`，
   v1.19.32）。Clash Verge 卸载/升级路径变了要改 `$MiExe`。
4. **不能按进程名杀进程**。本机常驻着 Clash Verge 自己的 `verge-mihomo.exe`，
   按名字匹配会把它一起杀掉。本脚本用 PID 文件 + ProcessName 校验做唯一凭据。

## 八、将来接 UDP 的可行方向

绕开 WinNAT 缺失（`Get-NetNat` 报 `0x80041010 WBEM_E_INVALID_CLASS`）的第三条路：

**在 pcs 上装 mihomo，开 `socks5` inbound 且 `udp: true`**。这是应用层 UDP relay，
源 IP 是远端自身，**不需要 NAT、不需要虚拟机**。本机再把这个 inbound 当作
`ferry-udp` 节点接进 `ferry-auto` 组即可。

这条路还没试。
