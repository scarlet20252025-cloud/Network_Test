# 架构与原理

> 这份文档回答三件事：**它到底怎么工作的**、**为什么这样设计**、**换一套怎么部署**。
> 想直接动手装，跳到最后一节；想排查故障，看 `docs/故障排查.md`。

---

## 一、要解决的问题

学校的网络策略是「按账号禁网」：

- 你的账号没有外网权限（或流量用完了、或被临时停用）
- 但**局域网是通的** —— 内网主机之间互相访问不受限

于是只要局域网里有一台「能上网的机器」（同学的本子、实验室的服务器、宿舍的软路由），
就可以让被禁的那台借它的出口上网。

这和 VPN / 机场的本质区别：**不需要公网 IP、不需要买流量**，
借的是「同一局域网里已经能上网的那台机器」。

## 二、总体拓扑

```
┌─────────────────────────┐        局域网         ┌──────────────────────────────┐
│ 被禁网的机器（客户端）    │                       │ 出口机 pcs / 10.13.24.1       │
│                         │                       │                              │
│  浏览器/下载器/游戏       │                       │  ferry-socks5-server.py      │
│        │                │   SOCKS5 (TCP)        │    :1080  TCP CONNECT         │
│        ▼                │──────────────────────▶│                              │
│  127.0.0.1:10801        │   UDP 中继            │  udp-relay (Python)          │
│  （HTTP+SOCKS5 同端口）   │──────────────────────▶│    :1080  转发 UDP            │
│        │                │                       │                              │
│        ▼                │                       │  portal-server.py :8080      │
│  本地双协议代理           │◀──────────────────────│    门户 / 管理 / 密钥 / 分发   │
│  （dual-proxy 逻辑）      │   HTTPS(HTTP)         │                              │
└─────────────────────────┘                       └──────────────┬───────────────┘
                                                                 │ 正常上网
                                                                 ▼
                                                            互联网
```

三块东西：

| 组件 | 位置 | 语言 | 跑法 |
|---|---|---|---|
| `渡口助手.exe` | 用户机 | C# WinForms (.NET FW 4.8) | 托盘常驻 |
| `ferry-socks5-server.py` + `udp-relay` | 出口机 | Python 3 | 计划任务 / 常驻 |
| `portal-server.py` | 出口机 | Python 3 | 计划任务（8080） |

## 三、三种工作模式

客户端支持三种把流量送出去的方式，**默认是「直连 SOCKS」**：

| 模式 | 链路 | 能覆盖谁 | 限速 | 加密 |
|---|---|---|---|---|
| **直连 SOCKS**（默认） | 本机 → `10.13.24.1:1080` | 认系统代理的程序 | ✅ 服务端按 IP 执行 | ❌ 明文 |
| **SSH 隧道** | 本机 → ssh -D → 出口机 | 同上 | ❌ 服务端只能看到一条连接 | ✅ 加密 |
| **TUN 全局**（可选） | 本机 → mihomo 虚拟网卡 → 上游 | **所有程序**（含游戏/QUIC） | ✅ | 取决于上游 |

为什么默认不用 SSH：

- SSH 的 `-D` 在服务端表现为**一个 TCP 连接**，服务端无法按「哪台机器」限速
- 每条连接都要走 SSH 加密/解密，吞吐和延迟都更差
- 直连 SOCKS 服务端能直接看到来源 IP，限速、封禁、统计全都做得了

代价是明文——同一局域网内可以嗅探域名和 IP。这是个**明确的取舍**，写在 README 的「限制」里。
要加密就在客户端设置里关掉「直连模式」，退回 SSH 隧道。

TUN 模式用 mihomo（clash 内核）建一块虚拟网卡，接管全部流量：

```
应用 → FerryTun 虚拟网卡 → mihomo → ├─ 直连目标（国内站）
                                    └─ 上游 SOCKS（出口机 / 远端 Clash）
```

分流规则在 `mihomo/config.template.yaml`，客户端启动 TUN 时会生成一份带当前端口的
`tun-config.yaml`。国内站直连、墙外走远端 Clash，是「竞速 + 优先窗口」实现的
（详见 `docs/出口旁路.md`）。

## 四、门户（portal）的三个角色

一个 Python 文件，三种用途：

1. **对用户**：介绍页、下载页、意见反馈
   - 下载页的「一键安装」返回一个十几行的 `.cmd`（见第七节）
2. **对管理员**：管理面板（`/admin`）
   - 密钥生成（一次性、绑定 IP、限时）
   - 在线机器、速率、连接数、流量统计
   - 意见反馈处理、限速热更新
   - 操作审计（events 表）
3. **对客户端**：几个 JSON 接口
   - `/version.json` 更新清单
   - `/api/license` 激活校验
   - `/api/config` 按 IP 下发配置
   - `/api/feedback` 接收反馈

数据库是 SQLite 单文件（`portal.db`），表：`invites` `sessions` `clients`
`traffic` `events` `feedback`。

**为什么不用框架**：门户要能在离线内网跑、不能有 pip 依赖、改一版就能 scp 上去重启。
标准库的 `http.server` + `sqlite3` 完全够，代价是路由和模板要手写（约 6000 行）。

## 五、鉴权与限速

**激活**：管理员在面板生成一个 8 位密钥（一次性、12 小时内有效、可指定授权天数），
用户把它填进客户端。客户端拿「密钥 + 自己的局域网 IP」去服务端换一个 token，
token 里带 `expiresAt`。之后每次启动只校验 token，不再用密钥。

**为什么密钥一次性**：泄漏了也只影响一次，且不能换机器用（绑定激活时的 IP）。

**限速**：在服务端做，按来源 IP 分配带宽。客户端改本地配置绕不过去。
实现是中继侧的令牌桶 + 配置热更新（`rate-mb.txt` 每 5 秒轮询一次，改了不断连接）。

## 六、UDP 怎么走

TCP 走 SOCKS5 的 `CONNECT`，这个所有代理都支持。UDP 麻烦得多：

- OpenSSH 的 `-D` **只实现 CONNECT，不支持 UDP ASSOCIATE**
- 所以另起了一个 Python 中继（`wireguard/` 下），客户端把 UDP 包发给
  `10.13.24.1:1080` 的 UDP 口，中继替它建 socket 发出去、把回包转回来

TUN 模式下 DNS 查询、游戏联机、语音都走这条路。实测完整链路 5/5 通，10–15 ms。

## 七、分发与更新：为什么有个 `.cmd`

安装包没有代码签名，浏览器下载后双击会弹 **SmartScreen**「Windows 已保护你的电脑」。
买 EV 证书（年费几千 + 企业资质）才能根治，自签名证书要用户手动装根证书、
还得人工点两次安全警告，**比 SmartScreen 本身更麻烦**，所以放弃。

绕过的原理很简单：

| 下载方式 | 会打 MOTW（来自 Internet 的标记） | 触发 SmartScreen |
|---|---|---|
| 浏览器点下载 | 会（`ZoneId=3`） | **会** |
| `WebClient` / `Invoke-WebRequest` | 不会 | 不会 |

所以下载页的主按钮指向 `GET /download-cmd`，返回一个 780 字节的 `.cmd`：

```bat
@echo off
chcp 936 >nul 2>&1            ← 文件是 GBK，代码页必须 936，否则中文乱码
set "URL=http://10.13.24.1:8080/download"
set "OUT=%TEMP%\Ferry-Setup.exe"
powershell -NoProfile -ExecutionPolicy Bypass -Command "…WebClient.DownloadFile…; Start-Process '%OUT%'"
```

用户双击脚本 → 脚本下载 → 文件不带 MOTW → 不触发 SmartScreen。
脚本只有十几行、可右键「编辑」看全，这是让人愿意双击它的前提。

**更新**：客户端启动时查 `/version.json`，有新版就下载 `Ferry-Setup-x.y.z.exe`
到 `%TEMP%`，然后以 `/SILENT /NORESTART` 启动安装包；安装器先调旧客户端的
`/stop`（还原系统代理），装完再由 `[Run]` 把新版拉起来。

> ⚠ 这套链路曾经有一整串 bug（Job Object、`/CLOSEAPPLICATIONS`、`skipifsilent`），
> 详见 `docs/踩坑记录.md` 第 29、44、45 条。

## 八、从零部署一套

### 8.1 出口机（Windows）

```powershell
# 1) Python 3（3.10+ 即可，标准库够用）
# 2) 放三个文件到一个目录，比如 C:\ferry-portal\
#      portal-server.py
#      ferry-socks5-server.py    (来自 wireguard/)
#      udp-relay.py              (来自 wireguard/)
# 3) 起门户
python C:\ferry-portal\portal-server.py --port 8080 --db C:\ferry-portal\portal.db --public-host 10.13.24.1
# 4) 起 TCP 服务端（监听 1080）
python C:\ferry-portal\ferry-socks5-server.py --port 1080 --rate-mb 10
# 5) 起 UDP 中继
python C:\ferry-portal\udp-relay.py --port 1080
# 6) 三个都注册成计划任务（开机自启、失败重试）
#    门户的 _deploy_remote.ps1 里有现成的 schtasks 例子
```

### 8.2 防火墙

```powershell
New-NetFirewallRule -DisplayName "Ferry Portal" -Direction Inbound -LocalPort 8080 -Protocol TCP -Action Allow
New-NetFirewallRule -DisplayName "Ferry SOCKS"  -Direction Inbound -LocalPort 1080 -Protocol TCP -Action Allow
New-NetFirewallRule -DisplayName "Ferry UDP"    -Direction Inbound -LocalPort 1080 -Protocol UDP -Action Allow
```

### 8.3 管理密码与首个密钥

```powershell
# 管理密码在首次启动时自动生成，写在 portal-admin.txt
# 打开 http://10.13.24.1:8080/admin 登录 → 「＋ 新建密钥」→ 弹出浮窗显示明文（只显示一次）
```

### 8.4 用户侧

```
下载页 → 点「⚡ 一键安装」→ 双击得到的 .cmd → 装完打开客户端 → 填密钥 → 开始借网
```

### 8.5 换一套（改 IP / 换出口机）

需要同步改的位置：

| 位置 | 改什么 |
|---|---|
| `portal/portal-server.py` 顶部 `CFG` | `public_host`、`ssh_user` |
| `ferry-client/src/Config.cs` 默认值 | `RemoteHost`（默认 10.13.24.1） |
| `installer/ferry.iss` 的 `PortalBase` | 门户地址 |
| `mihomo/config.template.yaml` | 上游地址与端口 |

更省事的做法：门户的 `/api/config` 会按来源 IP 下发完整配置，客户端首次安装
就从门户取——所以**只要门户地址对，其余大多数不用手改**。

## 九、设计取舍一览

| 决定 | 为什么 | 代价 |
|---|---|---|
| 客户端用 .NET Framework 4.8 而不是 .NET 8 | Win10/11 自带运行时，用户什么都不用装 | 只能用 C# 5 语法 |
| 门户用标准库而不是 Flask | 离线内网、零 pip 依赖、单文件可 scp | 路由/模板全手写 |
| 默认直连 SOCKS 而非 SSH | 服务端能按 IP 限速、吞吐更好 | 链路明文 |
| 默认不启用 TUN | 纯代理就能覆盖浏览器/下载/git，不需要管理员 | 游戏/QUIC 要用户手动开 |
| 客户端 `asInvoker` + 按需提权 | 装和启动都不弹 UAC，标准用户也能用 | 开 TUN 要一次 UAC + 重启 |
| 不开代码签名 | 自签名要用户手动装根证书，比 SmartScreen 更烦 | 浏览器直接下 exe 会被拦（有一键安装脚本绕过） |
| 安装到 per-user 目录 | 配置要频繁改写，放 Program Files 会触发 UAC 虚拟化 | 多用户共用一份程序时每人都要装一次 |
