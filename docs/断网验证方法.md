# 验证「断网后渡口还能用」— 操作说明

> 关键前提：学校的断网方式是「**禁用学生账号的上网权限，局域网仍然互通**」。
> 这正是本方案能生效的场景 —— SSH 走局域网到远端，不需要公网出口，
> 出公网那一段由远端办公网承担。

---

## 一、最省事的做法（推荐）

**用管理员 PowerShell 跑一条命令，全自动完成 + 自动恢复。**

1. 先确认渡口是开着的（GUI 显示「渡口中」，或跑过 `ferry.ps1 On`）
2. 按 `Win` 键 → 输入 `powershell` → **右键「Windows PowerShell」→「以管理员身份运行」**
3. 粘贴执行：

```powershell
powershell -ExecutionPolicy Bypass -File "E:\肥鱼不乐园\tools\verify-outage.ps1"
```

**它会自动做完这 5 步：**

| 步骤 | 做什么 |
|---|---|
| [0/5] | 记录断网前基线（SSH / 直连 / 渡口） |
| [1/5] | 加防火墙规则：放行 `10/8`、`172.16/12`、`192.168/16`、`127/8`，其余出站全阻断 |
| [2/5] | 确认公网**确实断了**（这是结论成立的前提） |
| [3/5] | 在断网状态下测 SSH + 4 个站点经渡口 |
| [4/5] | 保持 25 秒连续采样，看稳定性 |
| [5/5] | **无论成败都用 finally 还原防火墙** |

全程约 40 秒。期间本机无法上公网（包括 DSH 自己的模型调用），属预期 ——
所以脚本做成全自动，避免中途要人操作却连不上。

**输出示例（通过的样子）：**

```
[0/5] 断网前的基线
  SSH 到远端      : OK
  直连出公网      : OK
  渡口出公网      : OK

[1/5] 启用模拟断网（局域网通 / 公网断）
  已启用
[2/5] 确认公网确实断了（这是前提）
  直连 myip      : FAIL(000)
  直连 baidu     : FAIL(000)
  ✅ 公网已断，符合学校断网状态

[3/5] 关键验证：断网状态下渡口是否可用
  SSH 到远端         : OK
  github.com         : OK
  api.github.com     : OK
  baidu.com          : OK
  bilibili.com       : OK

================ 结论 ================
  ✅ 验证通过：公网被切断的情况下，渡口仍然可用。
     说明学校那种「禁用上网但局域网通」的断网，本方案能顶住。
```

## 二、真实断网验证（最有说服力）

如果你想用学校真实断网来验证（而不是我模拟的）：

1. 先开渡口
2. **启动后台监控**（这个窗口别关）：

```powershell
powershell -ExecutionPolicy Bypass -File "E:\肥鱼不乐园\tools\outage-watch.ps1"
```

它每 5 秒往 `.ferry\outage-watch.log` 写一行，记录三件事：
`直连 / 渡口 / SSH` 各自通不通。

3. 等学校断网（或让网管禁你的账号），等几分钟
4. 恢复后看报告：

```powershell
powershell -ExecutionPolicy Bypass -File "E:\肥鱼不乐园\tools\outage-watch.ps1" -Report
```

它会自动统计「断网期间渡口通了几次 / 断了几次」，并给出判定。

## 三、手动验证（只想快速看一眼）

断网后，在**普通 PowerShell** 里跑这两条对比：

```powershell
# ① 直连（绕过代理）—— 应该失败
curl.exe -s -o NUL -w "%{http_code}`n" --noproxy "*" --max-time 8 http://myip.ipip.net

# ② 渡口 —— 应该成功
curl.exe -s -w "`n" -x http://127.0.0.1:10809 http://myip.ipip.net
```

- ① 返回 `000`、② 返回 `200` + 一个联通 IP → **渡口生效**
- 两条都 `000` → 断的是 WLAN 接入层，SSH 也断了，方案救不了（见下）

---

## 四、怎么判断「断网类型」

| 现象 | 含义 |
|---|---|
| 直连 000，**SSH 到远端通**，渡口 200 | ✅ **学校这种断网，渡口有效** |
| 直连 000，**SSH 也断**，渡口 000 | ❌ WLAN 接入层断了（拿不到 IP / 路由没了），SSH 一起断 |
| 直连 200，渡口 200 | 没断成，重试 |
| 直连 200，渡口 000 | 渡口本身配置有问题，跟断网无关 |

**第二种情况为什么救不了**：渡口的隧道是 `ssh -D`，它本身就依赖本机能连到
远端（`10.13.24.1:22`）。如果 WLAN 都断了、连网关都不通，SSH 起不来，
dual-proxy 转发到一个没人监听的端口，全都失败。

**这正是为什么第 3 项要单独列出来** —— 你的学校是第一种（局域网通），
所以能救；如果是第二种，需要另一个物理通路（手机热点 / 随身 WiFi）。

## 五、出问题怎么恢复

如果脚本异常退出、防火墙规则没清掉，公网会一直断着。手动清：

```powershell
# 管理员 PowerShell
Get-NetFirewallRule -DisplayName 'Ferry-OutageSim-*' | Remove-NetFirewallRule
```

查看当前有没有残留规则：

```powershell
powershell -ExecutionPolicy Bypass -File "E:\肥鱼不乐园\tools\simulate-outage.ps1" -Action Status
```

也可以单独控制模拟开关（不自动恢复，需要你自己 Stop）：

```powershell
# 管理员
.\simulate-outage.ps1 -Action Start   # 开启模拟断网
.\simulate-outage.ps1 -Action Stop    # 恢复
.\simulate-outage.ps1 -Action Status  # 看状态 + 三项连通性
```

## 六、为什么这个验证有意义

不验证的话，你无法区分下面两种失败：

- 「渡口工具本身有问题」
- 「断网类型让渡口天然无法工作」

模拟断网（局域网通 / 公网断）恰好复刻了学校的实际断网方式，
所以它能干净地回答「**在学校断我网的情况下，渡口到底行不行**」这个问题。
