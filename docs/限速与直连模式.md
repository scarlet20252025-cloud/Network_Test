# 限速与直连模式（A 方案）

> 目标：让「每台机器 10 MB/s」这个限制**真正生效**。
>
> 代价：链路上是明文 SOCKS5，不再经 SSH 加密。

---

## 一、为什么原来的限速是假的

限速代码一直只存在于 `portal/dual-proxy.mjs`（Node.js，GCRA 按用户）：

```js
// dual-proxy.mjs:285
const rate = auth.store.settings.bytesPerSecPerUser || 0;
```

但客户端从 **0.8.0 起就不再启动 `dual-proxy.mjs`** 了 —— `FerryRuntime.cs` 改用
C# 内置的 `ProxyServer`，它没有任何限速和认证逻辑。检查结果：

| 检查项 | 结果 |
|---|---|
| `ferry-client/src/Proxy.cs` 里的 GCRA / limiter / rate | **0 处** |
| `wireguard/ferry-socks5-server.py` 里的 rate | **0 处**（改造前） |
| 运行时有没有 node 跑 dual-proxy | **没有** |

所以 `users.json` 里的 `bytesPerSecPerUser` 写了也白写，没有任何代码读它。

### 更麻烦的是：旧架构里限速**无处可放**

旧路径是 `客户端 → ssh -D → pcs sshd → 目标`。sshd 转发时源 IP 全变成
`127.0.0.1`，服务端根本分不清是哪台机器 —— 想限也不知道限谁。

## 二、A 方案：TCP 也直连远端 SOCKS5

```
客户端 ProxyServer(10801) ──┐
                            ├→ pcs:1080 (ferry-socks5-server.py) → 目标
客户端 TUN ─────────────────┘        ↑
                                  按源 IP 限速（GCRA，默认 10 MB/s）
```

改动三处：

1. **远端 `ferry-socks5-server.py`**：加 `RateTable` / `RateLimiter`（GCRA），
   按源 IP 限速，TCP 和 UDP 共用同一个 limiter（一个用户的总带宽）。
2. **客户端 `Proxy.Server`**：上游从「本机 127.0.0.1:ssh端口」改成
   「远端 IP:1080」，`ConnectSocks` 增加 `socksHost` 参数。
3. **客户端 `FerryRuntime`**：新增 `DirectSocks` 开关（默认开）。
   开启时完全不启动 ssh，直接连远端；关掉则退回 SSH 隧道模式（加密但限速失效）。

### 为什么用 GCRA 而不是令牌桶

令牌桶初始给满一桶，实测会瞬间超速 **2.4 倍**（项目里旧版 dual-proxy 踩过）。
GCRA 只维护「下一个包最早可发时间」，天然没有初始突发。

```python
def cost(self, nbytes):
    if self.rate <= 0: return 0.0
    now = time.monotonic()
    cost = nbytes / self.rate
    earliest = max(now - GCRA_TOLERANCE, self.tat)
    self.tat = earliest + cost
    return max(0.0, self.tat - now)
```

### 为什么按 IP 而不是按连接

一个人能开 40 条连接（`maxConnsPerUser`）。按连接限速等于把总配额乘 40，
限了跟没限一样。

## 三、实测

用「远端门户自己的安装包」当测试源（同一台机，局域网千兆，源速远超限速），
避免国际带宽干扰：

| 场景 | 实测 | 结论 |
|---|---|---|
| 限速设 0.5 MB/s，直连远端 1080 | **0.50 MB/s** | 精确 |
| 限速设 10 MB/s，直连远端 1080 | **10.03 MB/s** | 误差 0.3% |
| 限速设 10 MB/s，经客户端 10801 | **7.83 MB/s** | 含客户端转发开销 |
| 不走代理直连参照 | 34.64 MB/s | 局域网真实上限 |

## 四、踩过的三个坑

### 1. `--noproxy '*'` 又覆盖了 `-x`（自己踩自己）

验证限速时测得 34 MB/s，一度以为限速根本没生效、白查了一轮。

真相：命令里写了 `curl --noproxy '*' -x socks5h://...`，
`--noproxy '*'` 的意思是「对所有主机禁用代理」，**优先级高于 `-x`**，
请求根本没走中继，测的一直是直连速度。

这个坑在 [一键部署与UDP.md](一键部署与UDP.md) 里已经记过一次，结果自己又踩了。
**正确写法：只写 `-x`，不要加 `--noproxy`。**

### 2. `cmd.exe /c "...""..."...` 三层引号在 WMI 下会被拆坏

原来的启动方式是：

```powershell
$cmdline = 'cmd.exe /c "' + $args + ' >> "' + $LogFile + '" 2>&1"'
Invoke-CimMethod Win32_Process -MethodName Create -Arguments @{ CommandLine = $cmdline }
```

`$args` 里本身带引号（python 路径、脚本路径），三层引号嵌套后 cmd 解析出错，
python 拿到残缺参数**立刻退出**，但 `ReturnValue=0` 看起来像成功了。

表现：明明命令行里有 `--rate-mb 10`、文件也是新版，就是不限速 ——
因为**进程根本没起来，一直是旧进程在服务**。

修法：生成一个 `run-relay.cmd`（GBK + CRLF），一行一条命令，WMI 只运行这个
`.cmd`。没有嵌套引号，解析不会出错。

### 3. `Get-NetTCPConnection` 在 pcs 上查不到监听

部署脚本里改用「真的连一次」（`TcpClient.BeginConnect`），这是唯一可信的判据。

## 五、一键部署

```powershell
# 在 pcs 上
powershell -NoProfile -ExecutionPolicy Bypass -File deploy-udp-relay.ps1 -Port 1080 -RateMb 10
```

`-RateMb 0` 表示不限速。

---

## 六、安全提醒

直连模式下链路是**明文 SOCKS5**（没有任何加密）。同一个局域网里，
有人抓包就能看到你访问了什么域名和 IP。

现在的取舍：
- 校园网内部、可信环境 → 直连（能限速）
- 不可信网络 → 在客户端设置里关掉 `directSocks`，退回 SSH 隧道（加密，但限速不生效）

如果要两者兼得，需要给 SOCKS5 加 TLS 层（`sslsocket` 包一层，改动不大但
证书分发麻烦），目前没做。
