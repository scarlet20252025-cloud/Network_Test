# 局域网共享方案（预留设计）

> 状态：**设计稿，尚未实施**。当前 `--allow-lan` 参数已存在但默认关闭。
> 触发条件：需要让局域网内其他设备（手机 / 平板 / 另一台电脑）也用上借网。

---

## 一、当前架构与共享点的位置

```
现在（单机）：
  本机浏览器 ──系统代理──▶ dual-proxy(127.0.0.1:10809) ──SOCKS5──▶ ssh -D(127.0.0.1:10808) ──▶ 远端 ──▶ Internet

共享后（多机）：
  其他设备 ──HTTP/SOCKS──▶ dual-proxy(0.0.0.0:10809) ──SOCKS5──▶ ssh -D(127.0.0.1:10808) ──▶ 远端 ──▶ Internet
                              ▲
                         本机浏览器
```

**关键点：只需要改 dual-proxy 的监听地址，ssh -D 保持只听 127.0.0.1。**

理由：SOCKS5 端口（10808）没有认证，暴露到局域网等于给所有人一个开放代理。
dual-proxy（10809）可以加认证和 ACL，是唯一应该对外的一层。

## 二、启用步骤（最小改动）

### 2.1 打开监听

```powershell
# 停掉当前的
Get-CimInstance Win32_Process -Filter "Name='node.exe'" |
  Where-Object { $_.CommandLine -like '*dual-proxy*' } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }

# 用 --allow-lan 重启
$cmd = "`"D:\nodejs\node.exe`" `"E:\肥鱼不乐园\tools\dual-proxy.mjs`" --listen 10809 --socks 10808 --allow-lan"
Invoke-CimMethod -ClassName Win32_Process -MethodName Create -Arguments @{ CommandLine = $cmd }
```

### 2.2 放行防火墙

```powershell
# 需要管理员
New-NetFirewallRule -DisplayName 'BorrowNet Proxy' -Direction Inbound `
  -Protocol TCP -LocalPort 10809 -Action Allow -Profile Private
```

⚠️ **只对 Private 配置文件放行**，不要用 `-Profile Any`，
否则在公共 WiFi 下也会暴露。

### 2.3 客户端配置

| 设备 | 配置方式 |
|---|---|
| Windows | 设置 → 网络 → 代理 → 手动 → `http://<本机IP>:10809` |
| macOS | 系统设置 → 网络 → 代理 → 网页代理(HTTP) 填 `<本机IP>:10809` |
| iOS | WiFi → 配置代理 → 手动 → 服务器 `<本机IP>` 端口 `10809` |
| Android | WiFi → 修改网络 → 高级 → 代理 → 手动 |
| 命令行 | `export http_proxy=http://<本机IP>:10809` |

**注意：填 HTTP 代理，不要填 SOCKS。** 虽然 10809 也支持 SOCKS5，
但 iOS/Android 的系统级 SOCKS 配置在不同版本行为不一致，
HTTP 代理兼容性最好（这也是 dual-proxy 存在的理由）。

本机 IP 查询：`ipconfig | findstr IPv4`，当前是 `192.0.2.35`（学校 WLAN，会变）。

## 三、必须补的三件事（现在没做，别直接开）

### 3.1 认证（最重要）

当前 dual-proxy **无任何认证**。一旦 `--allow-lan`，同一 WiFi 下任何人都能用。

**最小方案：HTTP Basic Auth**

```javascript
// dual-proxy.mjs 里给 CONNECT 和普通请求都加一层
const AUTH = process.env.PROXY_AUTH;  // "user:pass"

function checkAuth(req) {
  if (!AUTH) return true;  // 未设则不限
  const h = req.headers['proxy-authorization'] || '';
  const m = h.match(/^Basic (.+)$/);
  if (!m) return false;
  return Buffer.from(m[1], 'base64').toString() === AUTH;
}

// httpServer.on('request' / 'connect') 开头：
if (!checkAuth(req)) {
  if (req.method === 'CONNECT') clientSocket.end('HTTP/1.1 407 Proxy Authentication Required\r\nProxy-Authenticate: Basic realm="borrow-net"\r\n\r\n');
  else { res.writeHead(407, { 'Proxy-Authenticate': 'Basic realm="borrow-net"' }); res.end(); }
  return;
}
```

**SOCKS5 也要加**：SOCKS5 支持用户名/密码认证（RFC 1929），
握手时返回 `0x02` 而不是 `0x00`，再走认证子协商。

### 3.2 访问控制（ACL）

只允许特定网段：

```javascript
const ALLOW_CIDR = (process.env.PROXY_ALLOW || '127.0.0.1,192.0.2.0/16').split(',');
// 在 net.createServer 的 connection 回调开头检查 socket.remoteAddress
```

**为什么需要**：学校 WLAN 是 `/22`（`192.0.2.35/22`），
一个网段可能有上千台设备，不开 ACL 等于给整个楼栋开代理。

### 3.3 连接数限制

防止单台设备跑满带宽：

```javascript
const MAX_CONN_PER_IP = 20;
const connCount = new Map();  // ip -> count
```

超限直接拒绝。理由：远端出口实测 90 MB/s 看着多，但经 SSH 隧道只有 36 MB/s，
几十个设备同时用会互相拖死。

## 四、性能预期（基于实测）

| 场景 | 预期速度 |
|---|---|
| 单设备 | 36 MB/s（实测，华为云源） |
| 3–5 设备同时 | 每个约 7–12 MB/s（分摊 36） |
| 10 设备以上 | 明显卡顿，不建议 |

**瓶颈是 SSH 单隧道**。如果确实要多设备高负载，需要：

1. **多隧道分流**：起多个 `ssh -D`（不同端口），dual-proxy 按源 IP 哈希分配
2. **多远端**：不同远端各起一条隧道，做负载均衡（工程量最大但最有效）

方案 1 的实现要点：`ssh -D 10808` / `ssh -D 10818` / `ssh -D 10828`，
dual-proxy 维护一个 `tunnels[]` 数组，`smartConnect` 时轮询或按
`hash(remoteAddress) % tunnels.length` 选一条。

**注意**：同一远端的多条 ssh -D 隧道不会提升总带宽（远端出口是共享的），
只有多远端才有意义。所以方案 1 只解决「单隧道并发连接数上限」，
不解决带宽。

## 五、安全提醒

共享代理 = 把你远端主机的网络身份借给别人用。风险：

| 风险 | 说明 |
|---|---|
| **流量可被记录** | dual-proxy 的 `--panel` 会记录目标地址，别对不可信的人开 |
| **远端主机背锅** | 别人用你的代理做违规操作，日志里是你的远端 IP |
| **办公网被封** | 远端在办公网，异常流量可能触发网络管理员介入 |
| **本机暴露** | `--allow-lan` 让本机的 10809 端口对内网开放 |

**建议**：
- 只对**自己控制的设备**开，不要给同事/同学
- 开认证，密码用长随机串
- 关掉 `--panel`（或只监听 127.0.0.1）
- 用完立即改回 `--allow-lan` 关闭
- 定期看 `Get-NetTCPConnection -LocalPort 10809` 有没有陌生来源
