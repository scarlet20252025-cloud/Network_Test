| 目标 | 直连 | 借网 | 差异 |
|---|---|---|---|
| `http://www.baidu.com` | 200，0.038s | 200，0.030s | 借网更快（噪声级） |
| `https://www.baidu.com` | 200，0.076s | 200，0.078s | 持平 |

**要点**：
- 借网**不是翻墙工具**。远端办公网同样出不了 google，google 失败与借网无关（直连也失败）。
- 国内站点延迟几乎无损（RTT 增量 3–14ms 量级），因为 SSH 走校内 3 跳直连。

## 三、抖动与丢包（20 次连续请求 baidu）

| 通道 | 成功 | min | p50 | p95 | max | 抖动(max−min) |
|---|---|---|---|---|---|---|
| 直连 | 20/20 | 0.030s | 0.036s | 0.059s | 0.059s | **0.029s** |
| 借网 | 20/20 | 0.031s | 0.097s | 0.164s | 0.164s | **0.132s** |

- 零丢包。
- 借网 p50 慢 **2.7 倍**，抖动放大 **4.55 倍**。
- 原因：每个请求要多穿 SSH 转发 + 远端 NAT 转发两段；SSH 单连接复用会串行化小请求。
- **影响**：网页浏览无感，但对延迟敏感的操作（游戏、实时交互、高频 API）会明显。

## 四、吞吐

用清华源 Ubuntu ISO（20s 限时）测：

| 通道 | 20s 内下载量 | 速度 |
|---|---|---|
| 本机直连 | 264.7 MB | **13.2 MB/s** |
| 本机借网（SSH SOCKS） | 21.1 MB | **1.05 MB/s** |
| **远端自身直连** | 19.9 MB | **0.95 MB/s** |

**关键结论**：借网 1.05 MB/s ≈ 远端自身 0.95 MB/s。
**SSH 隧道几乎零带宽损耗，瓶颈是远端办公网出口本身只有约 1 MB/s。**

所以：借网慢不是工具缺陷，是远端办公网的固有上限。要看视频/下大文件仍然不行。

## 七、❌ 致命发现：WireGuard 从未投入使用

取证：

```
Get-Service *WireGuard*        → 空（本机没装 WireGuard 客户端）
Get-NetAdapter *wg*            → 空（本机无 wg0 适配器）
tracert 10.13.24.1             → 3 跳：10.141.56.1 → 172.26.10.254 → 10.13.24.1
                                 （走校内网，不经 10.66.66.0/24）
远端 wg show dump              → peer clTyI1... latest handshake 从未发生
```

**结论**：WireGuard 只在远端搭了服务端（`WireGuardTunnel$wg0` Running/Auto，
监听 UDP 51820），本机从未安装客户端、从未握手。整套 WG 配置是死代码。

真正承载数据的是 `ssh -D 127.0.0.1:10808` 动态转发。

**这不影响当前功能**（SSH 通路实测良好），但意味着：
- 之前记录的「WireGuard 隧道 + SSH SOCKS」实际只有后半段成立；
- 想用 WG 承载必须先在**本机**装客户端并导入 `config/wg0-local.conf`。

## 八、⚠️ 最大单点：断网时靠什么连

用户的核心场景是「学校断网时借网」。当前链路是：

```
本机 ──[学校 WLAN 10.141.59.235/22]──→ 校内 3 跳 ──→ 10.13.24.1
```

**如果学校断网发生在 WLAN 接入层（拿不到 IP / 没有路由），SSH 根本连不上，
整套借网失效。**

已验证的回连通道状态：

| 通道 | 本机 | 远端 | 互通 |
|---|---|---|---|
| 学校 WLAN（当前主路） | 10.141.59.235/22 | — | ✅ 3 跳 |
| WireGuard 10.66.66.0/24 | **无客户端** | 10.66.66.1/24 Running | ❌ |
| Radmin VPN | 26.224.13.134/8（RvControlSvc Running） | **未安装** | ❌ 远端 ping 本机 = False |
| EasyTier | easytier-game 进程在 | **未安装** | ❌ |
| frpc 内网穿透 | **无** | 多个 frpc 进程在跑 | 未验证 |

**待决策**：要真正抗「学校断网」，必须有一条**独立于学校网络**的回连链路。
可选方向（需用户确认走哪条）：

1. **本机加第二物理链路**（手机 USB 共享网络 / 随身 WiFi）—— 最简单可靠，
   断网时切到手机网络，SSH 照样通。
2. **两端都装 EasyTier 或 ZeroTier** 组虚拟局域网 —— 仍需底层有网，
   但可跨网络（本机在手机热点、远端在办公网也能互通）。
3. **远端 frpc 反连** —— 远端主动连本机，但本机断网时同样连不上（方向不解决）。

> 只有当「断网」= 仅封外网出口、校内网仍通时，当前方案才直接可用。
> 这一点需要用户明确。
